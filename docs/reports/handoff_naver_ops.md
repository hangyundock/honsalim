## 2. 이식할 것 — ops 세션의 뼈대

`/naverblog-ops` (이름은 naver_blog 관례에 맞게) 를 만든다. 4단계 구조:

1. **점검(read-only)** — 브랜치·스케줄러 기동·발행 연속성·경보 이력·라이브 상태·측정 데이터
2. **심층 분석** — 원인 추적 + 성장 지표 추이 + 재고 소진 예측 + TODO 관찰 항목 소화
3. **실행 — 허용 범위 ONLY** — 그 외는 전부 '주인 결정 대기'로 강등
4. **보고** — `docs/reports/ops_YYYY-MM-DD.md` + 텔레그램 요약 + (이상/실행이 있었던 회차만) EVENTS

### ★반드시 옮겨야 할 안전 원칙 (혼살림에서 실제로 값을 한 것들)

- **실패 시 무변경**: 어느 단계든 이상하면 파일을 바꾸지 말고 보고 + 경보만 남기고 종료.
- **테스트 게이트**: 파일을 바꾸는 실행은 린터·회귀 전체 PASS가 선행 조건. 하나라도 실패 = 실행 취소.
- **허용 범위를 표로 못박기**: 무엇을 자동 실행하고 무엇을 제안만 하는지 애매하면 안 된다.
  혼살림 기준 — 허용: 씨앗 등재(원칙+테스트 통과분)·문서 갱신·커밋/푸시.
  금지(제안만): 글 비공개·통합, 카테고리/채널 공개, 발행 페이스·게이트·설정 변경, 코드 수정, 외부 게시.
- **새 예약 작업을 만들지 않는다**: 주간 작업은 **이미 매일 도는 경로의 요일 분기**에 얹는다.
  등록 작업이 늘수록 조용히 죽는 지점도 는다(혼살림 #43에서 detached HEAD로 10일 침묵한 전례).
  → naver_blog는 `daily_runner.py`가 매일 11:05에 도니 거기에 얹으면 된다.
- **파일럿 먼저**: 예약을 걸기 전에 **수동 호출로 1회** 돌려 실제 산출물을 본다.
